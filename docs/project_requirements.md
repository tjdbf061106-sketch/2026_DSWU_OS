# 기말 프로젝트 요구사항 추적

_수업에서 제공된 작업지침을 저장소 구조와 검증 기준으로 옮긴 문서입니다._

---

## 📋 필수 제출물

| 제출물 | 저장소 위치 | 완료 조건 |
|---|---|---|
| 재사용 가능한 Skill | `skill/` | 실행 코드, 사용 모델, 모델 저장소 링크, 적용 방법, 보고서 생성 지침 포함 |
| 최종 보고서 | `report/` | Solar Pro 4가 생성한 20페이지 이하 PDF 또는 DOCX |
| 실행 근거 | `runs/<run-id>/` | 입력, 모델 버전, 설정, 원본 출력, 오류 로그, 구조 이미지 보존 |

## 🔄 필수 동작 흐름

1. 대상 물질의 이름과 SMILES 등 구조 정보를 입력한다.
2. Skill을 읽고 지정된 실행 환경을 점검한다.
3. 합성 경로 예측 결과 또는 실패를 저장한다.
4. 각 유효 반응 단계의 합성 조건 예측 결과 또는 실패를 저장한다.
5. 각 유효 반응 단계의 수율 예측 결과 또는 실패를 저장한다.
6. 모델별 결과를 비교·통합한다.
7. 구조식 이미지를 포함한 최종 보고서를 Solar Pro 4로 생성한다.
8. 입력·모델 버전·실행 방법·산출물·오류를 보존한다.

## 🎯 평가 대응 원칙

| 평가 관점 | 저장소 대응 |
|---|---|
| 합성 정보 다양성 | 경로·조건·수율 결과를 별도 폴더와 통합 결과로 관리 |
| 보고서 가독성 | 구조식 이미지, 반응 단계 표, 명확한 한계 설명을 보고서 템플릿에 명시 |
| Skill 재현성 | `SKILL.md`, 로컬 설정 템플릿, 입력 JSON, 원본 실행 기록을 함께 보존 |
| 추가 분석 | 하네스 비교·MOPAC·EPI Suite·3D 분석은 선택 기능으로 문서화 후 추가 |

## ⚠️ 사실성 원칙

- 실제 실행 출력, 문헌 측정값, 예시, 미실행 항목을 분명히 구분한다.
- 예측 실패나 데이터 부족을 숨기지 않는다.
- Solar Pro 4 이외의 모델이 최종 보고서 본문을 작성한 결과를 제출물로 사용하지 않는다.
- 문체나 내용이 부족할 때는 사람이 본문을 고쳐 쓰지 않고 Skill·프롬프트를 수정한 뒤 Solar Pro 4로 다시 생성한다.
